## 1. 身份公理（I）——库是什么

### I1　薄组件库身份
Weave v0.4 是一个**组件库**，只做两件事：

1. **连接 LLM**（Provider）；
2. **连接环境/状态**（StateStore、ToolRegistry）。

其余一切（上下文如何构建、用什么循环策略、工具逻辑、Agent 间协作）**都不是库的裁决范围**，由使用方自定义。库提供原子能力，不提供"正确用法"的强制范式。

> **消解 I1 与组件数量的表面冲突**："只做两件事"约束的是**业务裁决边界**，不是组件数量。翻译循环（Loop）、上下文投影（ContextBuilder）、最小钩子（EventSink）属于**库机制**（把两件事接通所需的胶水与机制），不属于"第三件业务"。业务形态（循环策略怎么选、上下文放什么内容、工具怎么写）仍归用户（I3）。

来源：哲学文档 §1「只做两件事」；阶段三确认。

### I2　交付形态承诺线
- **接口 + 类型 = 唯一稳定契约**：只有 `core` 层的接口与共享类型进入向后兼容承诺。
- **默认实现 = 参考配方**：Agent、Default\*、InMemory/SQLite 等随包分发，支撑零配置与示例，但**明确不进入兼容承诺**，可被用户实现随时替换、可自由演进。
- **核心不依赖任何能力/配方**：能力层（事件流、server、scheduled、features 等）一律可插拔，核心组件不 import 它们。
- **"可选"的语义**：核心接口的"可选"指**装配时可缺省**（库提供默认、或可直接不提供），**不指契约强度可选**——凡随包公开的接口均进兼容承诺（ContextBuilder/Loop 亦然）。
- **正确性与稳定性是两条独立承诺轴**：参考配方不承诺 API 稳定（可自由演进），但在随包分发期间其**正确性**仍由库负责（I3）；用户以自实现替换后，正确性随实现转移。

来源：阶段三「接口=契约，默认=参考配方」；阶段一「其它作为 feature，可插拔，核心不依赖」。

### I3　责任边界
- **库负责**：接口契约、通信可靠性（重试/超时/错误分类）、**自带存储实现的正确性**（序列化 / TTL / 原子 / 并发）、最小钩子基础能力。
- **用户负责**：业务正确性——prompt 内容、上下文放什么、循环怎么选、工具怎么写、多 Agent 怎么协作。库对此不设强制范式、不替用户裁决。

来源：哲学文档 §5「最大自由 + 底层可靠」；阶段三「责任边界」确认。

### I4　对外叙事
对外身份叙事为**「组件库为体，DX 为入口」**：核心叙事是正交可组装的组件；Agent、CLI、yaml、零配置作为一等"快速上手入口"，但必须被明确标注为便利层。

来源：阶段三「身份叙事」确认。

### I5　DX 公理（已撤销——见修订注 R-2026）
> 本条目原描述"零配置 `Agent()` 默认装配 / 内置最小 system 覆盖 / yaml 装配器 / CLI init"等 DX 便利；
> 修订注 R-2026 已将其**移出 weave 交付范围**（weave 不再提供 Agent/CLI/weave.yaml 装配与零配置入口）。
> 如需要此类脚手架，作为调用方示例复制：`demos/atomic/`（含示例默认 system 与历史选址写法）。

## 2. 本质公理（A）——Agent 是什么

### A1　中介两面性
Agent 是 LLM 与外部环境之间的**中介**，天然拥有两个**正交接口面**：

- **LLM 面**：与模型交互。模型的"所见"由**上下文呈现**（投影结果）构成；
- **环境面**：与外部系统交互。环境的"所作/所感"通过**工具调用**完成（行动与感知）。

两个面**彼此独立、互不感知**。Agent 的核心循环只做一件事：**翻译**——把 LLM 的工具调用请求翻译为环境面动作，再把环境面结果翻译回 LLM 面的输入。

来源：用户提供的「两面性」推导（P6）。

### A2　面间正交
LLM 面与环境面互不感知：模型不感知工具内部实现，工具不感知模型/上下文机制。面与面之间只通过翻译循环传递**契约化数据**（schema、tool_call、tool_result）。

来源：A1 推论；先验 D1（正交性）在本质层的体现。

### A3　两面 + 一个环境基座（修正）
严格说 Agent 面对的不是"两面"，而是**两面 + 一个基座**：

- **StateStore = 环境基座**：持久状态/共享黑板，不属于任何一面；
- **ContextBuilder = LLM 面投影器**：把基座（及外部信息）投影为模型可见的上下文（系统提示/消息）；
- **ToolRegistry = 环境面执行器**：把 LLM 意图投影为外部动作/感知。

此修正取代"Memory 属于 LLM 面"的模糊表述：Memory/状态**存储**在基座，**呈现**经投影器进 LLM 面。

来源：两面性推导评审中第 3 处精化；阶段四确认。

### A4　翻译循环（Loop 的本质）
翻译循环是薄胶水，最小职责 = **调度 + 翻译 + 轮次持久化**：

1. 取上下文投影（ContextBuilder）；
2. 请求模型（Provider.complete）；
3. 若含 tool_calls → 逐条经 ToolRegistry 执行 → 结果回填为 tool 消息 → 回到 2；
4. 达到停止条件/上限则结束；
5. 每轮 user/assistant/tool 消息**写回私有流**（持久化是循环职责，保证多轮连续性）。

复杂性（重试、schema 转换、检索、裁剪等）**一律下沉到组件内部**，不进循环。

来源：先验 D4（薄编排）+ 阶段四确认。

## 3. 设计公理（D）——实现如何组织（先验五条，按逻辑序重排）

### D1　正交性（轴向独立可变）
模型通信、状态存储、工具执行是三个**正交维度**：互不依赖、可独立替换、可脱离 Agent 单独使用。能力轴同理：**搜索/时序裁剪等是"可选能力接口"**（如 `SearchableStore`），由后端自愿实现，核心循环不依赖，不进入 StateStore 必需方法。

来源：哲学 §2.1；阶段二「正交性」确认（搜索=可选能力接口）。

### D2　依赖倒置 + 最小钩子
- 高层控制流只依赖**抽象接口**，不依赖具体实现或具体容器实例（废除 v0.3 中 Loop 对 Weave 实例的鸭子类型依赖）。
- 横切点（事件、可观测）以**核心定义的最小钩子接口**表达——如 `EventSink.emit(type, data)`，**默认 no-op**；事件流、trace、checkpoint 等能力实现注入钩子，核心不 import 任何能力实现。

来源：哲学 §2.2；阶段二「依赖倒置」确认；阶段一"核心不依赖 feature"。

### D3　组合优于继承
- Agent 的行为由**组合组件实例**定义。
- **扩展 = 新的组件实现 + 实例注入**；不存在"继承 Agent/基类覆写方法"的定制范式（纯组合，无继承定制范式）。
- 默认实现允许子类化微调仅限实现内部便利，不构成对外推荐用法。

来源：哲学 §2.3；阶段二「组合优于继承」确认（纯组合）。

### D4　薄编排
循环不携带业务逻辑；可靠性、转换、检索、裁剪等复杂性位于组件内部；循环只保留 A4 的最小职责。

来源：哲学 §2.4；阶段二「薄编排」确认（Loop 留调度+轮次持久化）。

### D5　共享与隔离并存（黑板模式）
- 多 Agent 共享 = **存储层共享**：多个 Agent 实例可连接同一后端；共享/私有如何区分**由业务调用方决定**，weave 不定义任何分桶命名；
- **框架不提供 Agent 间协作/编排原语**：协作（发现、传话、互相调用）由用户业务自行实现；
- **命名零约定**：namespace/key 的取值、结构、语义全部由业务调用方决定（T7）。

来源：哲学 §2.5；阶段二「共享与隔离」确认（存储层共享，协作归用户）；阶段一基线。

## 4. 推导定理（T）——由公理导出的设计约束

### T1　原子工具接口组（"手"的抽象）
由 A1/A2（中介两面性 + 面间正交）+ D1（工具轴正交）导出：环境面收敛为极简原子接口组——

- `get_schemas() -> list[ToolSchema]`：供 LLM 感知可用工具（名称/描述/参数 JSON Schema）；
- `execute(name, arguments) -> Result`：执行工具并返回结果。

约束：
1. **schema 厂商中立**：`ToolSchema` 用规范形态（name/description/parameters JSON Schema），**厂商格式转换在 Provider 侧**（`complete()` 前），ToolRegistry 不感知 OpenAI/Anthropic/DeepSeek 差异。
2. **工具 = 行动 + 感知**：环境面不只是"副作用动作"，还包括模型无法直接执行/不该直接访问的查询与检索（知识检索可作为挂在 ToolRegistry 上的检索工具，或作为 Store 可选能力，二者并存不互斥）。
3. **注册/推断/便捷绑定（`@tool`、类型注解推导、同步函数线程池等）属于 ToolRegistry 的参考配方层**，不是原子契约；非 Python 工具实现两方法即可接入。
4. **增强层不破坏抽象**：权限、限流、流式、审计以**同接口的包裹实现**（代理 Registry）叠加。
5. **错误通道**：执行失败抛类型化错误，由翻译循环捕获并转写为 tool 错误消息（不崩整次 run；可设最大连续错误次数）。

落地位置：`ToolRegistry` = 本接口组的具体化；翻译循环经它完成 A4 步骤 3。

来源：用户「两面性 → 原子化」推导（P7）；可行性评审五处精化。

### T2　Provider 内嵌可靠性
由 I3（库管通信可靠性）+ D4（复杂性下沉组件）导出：重试/超时/错误分类**内嵌在 Provider**，独立使用 `Provider` 也可靠；不再由编排层持有。

约束：
1. **错误类型保留并暴露**：调用方可区分"业务错误（不可重试）"与"重试耗尽"；复用类型化错误分类（429 可重试、401/403/400/422 不可重试、5xx 可重试、402 等业务错直接抛）。
2. **超时语义明确**：单次调用超时 vs 整重试序列硬上限，二者语义须写明并都可配置。
3. **流式重试语义单独定义**：已吐出的 token 不可撤回——流式重试策略（不重试 / 从头重启并丢弃前半段）须显式规定。
4. 重试参数化（attempts/backoff/上限）作为 Provider 构造/调用参数，不再寄生于 `loop.*` 配置命名空间。

### T3　投影与执行的分工
由 A1–A3 导出三分职责：`ContextBuilder`（LLM 面投影：读基座 + 组装上下文）、`ToolRegistry`（环境面执行）、`StateStore`（环境基座）。三者接口互相独立，仅通过翻译循环与投影时机发生关系。

### T4　可观测 = 钩子注入
由 D2（最小钩子）+ I2（核心不依赖能力）导出：翻译循环在执行关键点调用 `EventSink`（事件级如 loop_start/iteration/llm/tool/loop_end/error——**仅示意**，最终事件集随 04-capability 定稿，见 §8-4），默认 no-op；observability（trace/落盘）、checkpoint、事件流、server 均为**能力层**实现并注入钩子，互不依赖。

### T5　Agent = 装配容器
由 D3（纯组合）+ A1（中介本质）导出 Agent 形态：

```
Agent(provider, state_store,
      tool_registry=None, context_builder=None, loop=None,
      *, agent_id="default")
```

- `async call(user_input, **kwargs) -> AgentResult`（含 output / elapsed / iterations / usage / writes 等元数据）；
- `agent_id` 是**通用标签**（含义与用途由业务调用方决定；默认 "default"），不允许运行时 getattr 兜底；是否按 agent 隔离/共享由调用方在历史选址（T7）中自行实现；
- Agent 自身保持薄：同步入口、流式便利、checkpoint、observability 均由 **DX/能力层**包装 Agent 提供；
- 无参 `Agent()` 的默认装配见 **I5**；
- **共享同一后端的多 Agent 必须显式传唯一 `agent_id`**：默认 `"default"` 只适用于单 Agent/隔离场景，缺省时多个实例会写入同一 `agent:default:*` 私有域而互相串扰——身份管理归调用方（呼应 D5）。

### T6　对话轮次的存储表达
由 A4（循环持久化职责）+ D1（存储最小必需方法）导出：多轮对话 = `(namespace, key)` 下的**有序列表**——`append` 追加、`get` 读全量；裁剪（预算控制）为可选能力或投影器职责。

### T7　命名与字段零约定（决策）
由 D5 导出（**决策**，非推荐约定）：weave 不定义任何业务命名/分桶约定——

- 核心与参考配方中不把 `shared` / `agent` / `stream` / `state` / `knowledge` / `messages` 等词用作语义默认；
- 会话历史的读写位置由业务调用方经 ``locate_history: (agent_id) -> (namespace, key)`` 显式注入；未提供则不持久化（无状态单回合；T6 的有序列表可用于调用方定义到的任何位置）；
- DX 装配描述里的 ``conversation.namespace/key`` 亦为调用方声明（namespace 可含 ``{agent_id}`` 占位），weave 只做替换、不做解释；
- StateStore 把 namespace 视为**不透明字符串**：不解析、不强制、不预设语义。

### T8　StateStore 参考实现
由 I2（配方）+ D1（可选能力）+ T6 导出随包参考实现：**InMemory**（默认/测试）+ **SQLite**（WAL，单机持久）+ **Redis**（可选 extra，多进程共享）；搜索/裁剪按 D1 以可选能力接口提供。

## 5. 分层与依赖规则

```
DX 层        yaml/env 配置体系 + 组件装配器(from_config) + CLI + 零配置/同步/流式便利
能力层       可插拔：observability / checkpoint / 事件流+Server / scheduled / features
高层封装     Agent（装配容器；可选，可绕过）
核心层       接口+类型（唯一契约）；Provider / StateStore / ToolRegistry /
             ContextBuilder / Loop / EventSink；参考配方随包但不进契约
```

**依赖方向**：上层依赖下层接口；核心层**不 import** 任何上层（能力/配方/DX）。**契约线**：只有核心层接口与类型进兼容承诺。

## 7. 术语表

| 术语 | 定义 |
|------|------|
| Provider | 核心接口：连接 LLM；内嵌可靠性；`complete()/stream()`；厂商中立工具 schema 在此转换 |
| StateStore | 核心接口：环境基座；必需方法 get/set/append/delete（async）；可选能力接口承载搜索/裁剪 |
| ToolRegistry | 核心接口：环境面执行器；`get_schemas()/execute()` 原子接口组（T1） |
| ContextBuilder | 可选核心接口：LLM 面投影器；`build(...) -> 消息列表` |
| Loop | 可选核心接口：翻译循环（A4），薄胶水 |
| EventSink | 核心最小钩子：能力层注入点，默认 no-op（T4） |
| Agent | 高层封装：装配容器（T5），可选 |
| 参考配方 | 随包默认实现：不进兼容承诺（I2） |
| 能力层 | 可插拔功能（observability/checkpoint/事件/server/scheduled/features） |
| DX 层 | 便利入口：yaml 装配器 / CLI / 零配置 / 同步与流式包装 |
